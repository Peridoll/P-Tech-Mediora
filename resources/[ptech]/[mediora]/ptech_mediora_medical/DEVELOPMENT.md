# Mediora Medical 開発資料

このファイルをMedicalの開発・引き継ぎ用の正本とする。実装の根幹は「診察 → 一時カルテ → アイテムで治療」。画面の細部は仮置きで、小さな工程ごとに進める。

## 現在の状態

| 工程 | 設計・実装 | 確認状況 |
| --- | --- | --- |
| 診察開始 | /pmedical diagnose [ID]。ID省略で近くの他プレイヤー。ox_targetからも同じ診察処理へ進む。短縮コマンドなし | Lua模擬実行。実サーバーで負傷形式エラーの報告あり |
| 権限と対象確認 | 許可職業かつ勤務中。サーバーで距離・バケット・対象・診察者の状態を再確認 | Lua模擬実行 |
| 診察演出 | 基本1秒＋取得できた負傷1部位につき1秒、上限6秒。タブレット演出、対象への「診察されています」、中止処理 | コード実装済み。実機での演出・通知の確認が必要 |
| カルテ保存 | 診察完了時にサーバーメモリへ保存。勤務中の許可職業で共有。患者のcitizenidで管理し、再起動で消去。DB・アイテム化なし | Lua模擬実行 |
| カルテ一覧・詳細 | Medical単体のNUIを追加。診察後に作成したカルテを開く。ターゲット「治療する」は対象ID入りのカルテ一覧を開く。患者ID検索・過去の診察の選択。context表示にも対応 | Lua 11件・Chromium試験通過。FiveM実機は未試験 |
| 負傷形式エラーの確認 | 未対応形式なら取得データの画面を開く。無傷として保存しない | 模擬データで確認。実際のWasabi返却形式は未確認 |
| 治療・アイテム消費・治療履歴 | 未実装。現在のカルテ画面は閲覧のみ | 未試験 |

現在のv4ツリーには旧EMSManagerリソースがない。Medical側にカルテ閲覧画面を持たせた。旧Managerが別途起動している場合、診察後の既存連携は維持し、起動失敗時はMedical内の画面へ進む。

## 確定した基本仕様

- 許可職業はConfig.Jobs。勤務中限定は固定仕様で、切り替え設定を設けない。
- 入口がコマンドでもターゲットでも診察本体は共通。サーバーで最終判定する。
- 7部位は頭部・上半身・下半身・左腕・右腕・左脚・右脚。Wasabiのキーは順にhead / upper_body / lower_body / left_arm / right_arm / left_leg / right_leg。
- カルテは診察時点の記録。自動更新しない。接続中の患者をサーバーIDで検索し、そのcitizenidに紐づくカルテを返す。
- 負傷情報の取得失敗・未対応形式・空の返却値は区別する。空の返却値を健康の保証にしない。現実装では負傷行がない場合にカルテは作らない。
- 仮作成したMedicalアイテムは廃止済み。将来Logiのアイテムを取り込む。今回アイテム追加・既存アイテム変更は行っていない。

## 次の工程

1. 実サーバーのWasabi返却データを採取し、診察の形式エラーを解消する。
2. Logiの採用アイテムと、Wasabiの傷・必要数・治療時間を対応づける。
3. カルテから治療へ進み、アイテムを部位へ置いた時点で開始する。成功時に消費する。中止・距離変化・切断・同時操作を考慮する。

その後の設計として、一括治療、治療履歴と合計金額、タブレットのホーム・アプリ・画面保持がある。一括治療時間はユーザー案の「基本時間 × (2 + 0.2 × 使用総個数)」を出発点とする。対象単位や端数処理などは治療実装時に詰める。腕の照準ぶれの廃止、脚・腰の重い打撲に伴う骨折とアクション時のラグドール、過去の瀕死・死亡時間の記録も未実装。これらをカルテ閲覧の完了条件に混ぜない。

## Wasabi連携と既知の問題

現在のパーサーが対応する形は次の通り。これは現実装の入力形式であり、導入中の旧版Wasabiで実測済みの形式ではない。

    injuries[部位] = {
        type = 'shot' または 'stabbed' または 'beat' または 'burned',
        data = { level = 0〜4, bleed = 0〜4 }
    }

診察時に「負傷情報の形式に対応していません」と報告されている。実際の返却データが未取得のため、パーサーの根本修正は保留中。今回の変更後はエラー時に開く診察画面の「取得データを確認」で内容を確認できる。必要ならConfig.Debugをtrueにし、F8の次の行と、その後のinjuriesの内容を採取する。

    [ptech_mediora_medical] serverId=... success=... returnType=...

取得データは診察者クライアントからの観察値。サーバーは権限・患者同一性・距離・演出時間を検証するが、Wasabiの負傷そのものをサーバーで照合していない。今後のアイテム消費や治療成功判定に、この観察値だけをそのまま使わない。

## ファイルと連携口

| 場所 | 内容 |
| --- | --- |
| config/config.lua | 手修正する設定 |
| main/shared/shared.lua | 職業・勤務・死亡判定、負傷の正規化 |
| main/server/server.lua | 診察許可、診察中通知、カルテ保存と検索 |
| main/client/client.lua | コマンド・ターゲット入口、Wasabi取得、診察演出 |
| main/client/ui.lua | NUI/context、権限確認、照会中断・応答の世代管理 |
| main/ui/ | 診察結果・カルテ画面 |
| tests/ | FiveM APIを置き換えるLua実行試験とブラウザ試験 |

クライアントexport：

    exports.ptech_mediora_medical:openCharts(patientServerId, optionalChartId)

NUIならIDを省略して検索画面を開ける。contextでは患者IDを渡す。画面を開く際と検索する際の両方で、サーバーが職業・勤務を確認する。返り値は表示時true、取得失敗時false、照会中に終了した場合nil。

getTreatmentItems exportは互換用に空の一覧を返す。アイテムはまだ治療に使えない。

## 自動試験

このリソースのディレクトリで実行する。

    python -m pip install -r tests/requirements.txt
    python -m unittest discover -s tests -v

ブラウザ試験はNode.js・playwright・Chromiumが必要。例えば試験用ディレクトリにplaywrightを導入して実行する。

    npm install --prefix /tmp/medical-ui-test playwright@1.62.1
    /tmp/medical-ui-test/node_modules/.bin/playwright install chromium
    NODE_PATH=/tmp/medical-ui-test/node_modules node tests/test_charts_ui.cjs

既存のChromiumを使う場合はCHROMIUM_EXECUTABLE_PATHを指定できる。今回の環境ではChromiumを別途展開して使用した。Lua 11件、NUIの検索・選択・権限エラー表示・空データ・入力検証・文字列の安全な表示・遅延応答の破棄・閉じる操作・7部位・1280×720と1920×1080の表示を確認済み。

これらはFiveMとWasabiの実機試験の代替ではない。

## 次の実機確認

1. 負傷した患者へ /pmedical diagnose ID。形式エラーなら取得データを採取する。
2. 対応する負傷情報で診察が完了したら、対象への診察中通知が消え、作成したカルテが開く。
3. 画面を閉じ、同じ患者をターゲットして「治療する」。患者IDとカルテ一覧が入る。
4. 患者IDを変更し、未接続ID・カルテなし・複数のカルテをそれぞれ確認する。
5. 別の勤務中医療職でも同じカルテを閲覧できること、勤務を外すと再検索が拒否されることを確認する。
6. 診察中止・照会中のログアウト・リソース再起動で画面や診察中通知が残らないこと、再起動後のカルテが空になることを確認する。
