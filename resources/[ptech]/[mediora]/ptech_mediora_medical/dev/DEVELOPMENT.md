## 導入・切替

1. 既存のMedicalを今回のリソースへ置き換える。リソース再起動でカルテ・傷・履歴を消去する。新しいセッションからのダメージが記録対象となり、過去のWasabi内部データの移行は行わない。
2. install/wasabi_ambulance.lua のコメントに従い、wasabi_ambulance/game/configuration/config.lua の既存設定を変更する。EnableLiveInjury=false等でWasabi側の負傷・出血・照準への干渉と重複させない。Wasabiの死亡・laststand・蘇生は継続使用する。蘇生時に空腹・渇き・ストレスを維持する場合は、同じ手順に従い game/client/client.lua の蘇生2か所も変更する。
3. install/ox_inventory/items.lua を参照し、ox_inventory/data/items.lua の対応アイテムを統合する。同じIDを二重登録しない。Tools等で定義済みなら既存項目を編集する。自己使用アイテムはconsume=0とclient.exportをセットで設定する。
4. ox_lib、ox_target、qbx_core、wasabi_ambulance、OneSyncを起動する。治療・道具所持確認にはox_inventoryも起動する。
5. Wasabiとアイテム定義を含む導入元リソースを再起動し、最後にMedicalを再起動する。Wasabiの既存アイテムイベントをMedicalの自己使用exportへ重ねない。

installは手動導入例だけを置く場所。fxmanifestへ登録せず、既存リソースや入手経路を自動変更しない。同梱の install/ox_inventory/images/ の画像は必要に応じて ox_inventory/web/images/ に配置する。

## 最終設計：受傷と蓄積

7部位：head（頭部）、upper_body（上半身）、lower_body（下半身）、left_arm、right_arm、left_leg、right_leg。

- 各部位に鈍症蓄積値bluntと鋭症蓄積値sharpを別々に保持。初期0、上限90。
- 加算単位は最大の行動可能体力に対して失った割合。通常のGTAペドでは行動不能側の基準100を除き、最大HP－Config.Wounds.HealthBaseを100%とする。導入先のHP仕様が異なる場合はHealthBaseを調整する。
- 例：行動可能体力100のうち20を失うと20を加算。固定のGTA生HP値20を、常に20%とみなすわけではない。
- 殴打・衝突・転落：打ち身を発生し、鈍症へダメージ割合を加算。
- 切り傷：鋭症へダメージ割合を加算。
- 銃創：鈍症へダメージ割合×1.25、鋭症へ×0.75を加算。旧案の1.5／0.5は使用しない。
- 火傷：炎・爆発を分類。新たな火傷発生時に同じ部位の鋭症＋10。継続する火傷を毎秒＋10する処理ではない。
- 通電ピン：スタンガン2種の命中で発生。HPが減らなくても記録する。保持中の患者は火傷ダメージ2倍。摘出で解除する。
- 不明な原因は無条件に打ち身へ変換しない。武器名の個別分類はConfig.Wounds.WeaponKindsに記載。未登録の銃器はGTAの武器ダメージ種別で分類する。
- 部位はGetPedLastDamageBoneで分類し、取得できなければ設定のFallbackPartへ仮分類する。事故・炎などで正確な接触部位を保証するものではない。複数の被弾が同じフレームに集中する場合はHP実減少がまとめられる可能性がある。
- 体力が減らない防具だけのダメージは蓄積させない。通電ピンは例外。

医学上の名称・治療効果の再現ではなく、Mediora内のゲーム規則である。

## 打撲・骨折の抽選

受傷原因で打ち身と打撲を別カテゴリにする案は採用しない。打ち身が基本で、打撲の抽選に当たると同じ部位の打ち身を置き換える。

1. ダメージ分を鈍症へ加算する。
2. 鈍症蓄積値−5%で打撲抽選。負の確率は0%として扱う。
3. 当選時、打ち身を除去して打撲を発症・維持し、鈍症＋5。既存の打撲への再当選でも毎回＋5。
2. 打撲中の鈍症の下限を30へ補正し、上限90以内に収める。
5. 加算後の鈍症蓄積値−30%で骨折抽選。当選時は骨折を発症、緩和中なら再悪化する。

既存打撲があっても新たな受傷ごとに手順2から判定する。打撲抽選に外れた場合は既存打撲を保持し、その回は骨折抽選しない。例：受傷後70→打撲65%→当選で75→骨折45%。

死亡・瀕死への移行を伴う打ち身は確率に関係なく打撲化し、その打撲通知を出さない。サーバー側の死亡フラグが遅れて届く場合も、直近受傷と照合して補正する。診察や定期観察だけで骨折を新規発生させない。

| 表示 | 判定 | 冷却道具の必要個数 |
| --- | --- | ---: |
| 軽度の打ち身 | 打ち身状態、鈍症30以下 | 1 |
| 重度の打ち身 | 打ち身状態、鈍症30超 | 2 |
| 軽度の打撲 | 打撲状態、鈍症60以下 | 3 |
| 重度の打撲 | 打撲状態、鈍症60超 | 4 |

骨折は7部位に保持できる。アクション時の転倒は下半身・左右脚に適用する。腕の照準ぶれは追加しない。

## 出血

- 切り傷・銃創の新たな受傷で抽選する。最終資料の明記に従い、基準は鈍症蓄積値。鋭症へ自動で読み替えない。Config.Wounds.BleedingBasis='sharp'に変更すれば鋭症基準へ切り替えられる。
- 加算後の値で判定。当選で出血を発症／再悪化し、鋭症＋5。
- 切り傷による死亡・瀕死では確率に関係なく出血し、その出血通知を出さない。
- 発症中は毎秒、最大の行動可能体力の2%ダメージ。複数部位で出血してもこの定期ダメージを部位数倍にはしない。死亡・瀕死中は追加しない。
- このダメージ自体による蓄積増加・受傷抽選は行わない。
- 止血剤で緩和すると定期ダメージを停止する。緩和状態を保持し、新たな受傷時の出血抽選へ20ポイント加算する。当選したら再悪化。

## 回復・治療

- 医薬品で実際に体力を回復した際、全7部位の鈍症・鋭症を1使用につき半減する。打撲がある部位の鈍症は最低30。
- 回復アイテムで全快に達した場合、切り傷を解除し、打ち身は15分後に解除する。同じ部位を再び打った場合は打ち身の解除予定を取り消す。冷却で治療した場合はすぐに解除する。打撲・銃創・火傷・通電ピン・骨折・出血は別処置が必要。
- 1分ごとに蓄積値を1減らす。打撲中の下限30は維持。発症中の打撲・骨折・出血そのものを時間経過で解除しない。減少はログイン中に適用し、サーバー再起動で状態は消える。
- EMSの冷却・骨折処置後は鈍症、縫合・銃創・止血処置後は鋭症を最大30へ抑える。既に30未満の値を引き上げない。打撲が残る場合の鈍症下限は継続する。

| 道具 | 効果 |
| --- | --- |
| 救急キット | 体力を全快まで回復。蘇生は行わない |
| 医療用包帯 | 体力15%回復＋選択部位を止血 |
| 冷却スプレー／冷却パック | 打ち身・打撲を治療。骨折は残す |
| 縫合キット | 切り傷を治療＋同じ部位を止血 |
| 針と糸 | 切り傷を治療。止血は別 |
| 弾丸摘出キット | 銃創・通電ピンを摘出＋同じ部位を止血 |
| 医療用ピンセット | 銃創・通電ピンを摘出。止血は別 |
| 薬品包帯 | 火傷を治療＋同じ部位を止血 |
| 火傷クリーム | 火傷を治療。止血は別 |
| 保護ギプス | 選択部位の骨折を治療。打撲は残す |
| 鎮痛剤 | 選択部位の骨折を緩和。完治ではない |
| 止血剤 | 選択部位の出血を緩和。完治ではない |

切り傷は鋭症20以下で軽度・20超で重度、必要数1／2。最終資料の切り傷欄に残っている「打ち身」「鈍症」の表記は、その欄の主題に合わせて切り傷・鋭症として実装した。打撲の軽重欄の「打ち身」も打撲として扱う。

資料で必要数が未指定の銃創・火傷・通電ピン・ギプス・薬は初期1個。処置時間は初期1個2秒、冷却スプレーのみ1秒。冷却スプレーの2個分換算は会話の提案段階だったため、最終資料に合わせ個数換算は初期1倍にしてある。いずれもConfig.Wounds.Itemsのpower・durationで調整できる暫定値。新規アイテムIDはinstall/ox_inventory/items.luaにまとめた。

患者単位で同時処置をロック。サーバーで開始・終了の両方に職業、勤務、同一キャラクター、距離、バケット、所持個数、必要処置、経過時間を検証する。完了前の新たな受傷や別の処置で状態が変われば中止し、再確認を要求する。途中中止・画面を閉じる・別患者を検索・退勤・切断・アイテム不足では消費しない。同じ完了要求を再送しても重複消費しない。

再診で新しい傷や悪化がなければ最新カルテを使う。作成から5分以内は、未請求のカルテへ傷を追記する。請求済みなら傷の有無にかかわらず、次の診察で新規カルテを作る。蘇生後に再びダウンした場合も新規カルテを作る。新規作成後は過去カルテの治療と請求を無効にし、閲覧は引き続きできる。最新カルテの治療欄には現在の症状・所持道具・患者ごとの治療履歴を表示する。

## 骨折の行動症状

- 脚・下半身の発症中骨折：ジャンプ・登り・乗り越え・ダイブ／回避動作で転倒。
- 緩和中骨折：転倒の代わりに1%のダメージを受ける。このダメージを骨折部位の打ち身として再処理し、打撲抽選→当選時の骨折抽選で再悪化する可能性がある。
- 発症中と緩和中が複数部位にある場合は発症中の転倒を優先。1動作で部位数分のダメージを与えない。
- 死亡・瀕死・車内・水泳・潜水・アタッチ中・既に転倒中は追加の転倒処理を行わない。連続発動間隔はConfig.Fractureで調整。
- 独自スライディングは導入元から開始／終了をexportで通知する。GTA標準にないアニメーションを自動判定できるとは扱わない。

## Wasabi・Toolsとの境界

Medicalは傷・蓄積・治療のサーバーメモリを持ち、Wasabiは死亡・瀕死・蘇生を担当する。従来のdiagnosePlayer返却形式に依存しないため、新方式の診察で「負傷情報の形式に対応していません」を要求条件にしない。ただしWasabiの未知形式を解析・移行できるようになった意味ではない。

自己使用アイテム以外の既存回復薬を継続利用する場合、その成功処理からサーバーexportを1回呼ぶ。HP増加だけを監視して半減すると自然回復や蘇生まで薬と誤認するため、その自動推定は行わない。

    exports.ptech_mediora_medical:recordMedication(patientServerId, reachedFullHealth)

Medicalの自己使用経由では内部で適用済み。重複呼び出ししない。

    -- サーバー：状態のコピーを取得
    exports.ptech_mediora_medical:getWounds(patientServerId)
    exports.ptech_mediora_medical:getFractures(patientServerId)
    exports.ptech_mediora_medical:clearFractures(patientServerId, optionalPart)

    -- クライアント：既存タブレット等の連携口
    exports.ptech_mediora_medical:openCharts(patientServerId, optionalChartId)
    exports.ptech_mediora_medical:getTreatmentItems()
    exports.ptech_mediora_medical:setMedicalSliding(true) -- 終了時はfalse

クライアントはダメージ原因・HP実減少・骨IDを報告する。サーバーは報告先を本人に限定し、セッション・連番・範囲・頻度を検証し、抽選・消費を管理する。ただしクライアントのダメージ観測をサーバーだけで独立検証するアンチチートではない。

## プログレス表示

Core が稼働している場合、診察・治療・蘇生の進捗を Core の画面中央下の共通バーに表示する。Core タブレットで選んだ色テーマを使用し、完了・中断で該当するバーを閉じる。Core がない環境では従来表示に戻る。

## 管理者の負傷・ダメージ試験

ゲーム内で引数なしの /medinjury または /meddamage を実行すると、それぞれの設定画面が開く。画面から実行するときも同じ ACE 権限が必要。

- /medinjury <患者ID> <部位> <傷> [重さ・状態] は HP を変えずに指定の傷を付ける。例 /medinjury 12 right_leg bruise heavy。
- 部位は head、upper_body、lower_body、left_arm、right_arm、left_leg、right_leg。
- 傷は blunt（打ち身）、bruise（打撲）、cut（切り傷）、shot（銃創）、burn（火傷）、pin（通電ピン）、fracture（骨折）、bleeding（出血）。打ち身・打撲・切り傷には light / heavy、骨折・出血には active / suppressed を任意で指定できる。
- /meddamage <患者ID> <HP> は指定した分だけ現在のゲーム内 HP を減らす。0以下になる場合は0で止める。例 /meddamage 12 25。
- サーバーコンソールで実行できる。ゲーム内から実行する場合は command.medinjury / command.meddamage の ACE を個別に付与する。

## 点滴と餓死の実機試験

1. install/ox_inventory/items.lua の pmediora_ivdrip を稼働サーバーの ox_inventory/data/items.lua に統合する。対応画像は install/ox_inventory/images/pmediora_ivdrip.png。
2. 管理者は /medkit30 で点滴を補充できる。点滴は医療職がカルテの治療画面で人型のどこにでもドロップできる。ドラッグ中に人型へ重ねると7部位が光る。餓死・溺死の部位欄は「-」と表示する。ダウン中に点滴を1個消費して所見を処置すると、蘇生の前提が満たされる。餓死は空腹・水分を各20ポイント回復し、ストレスを20ポイント軽減する。溺死は点滴で所見のみ処置し、空腹・水分・ストレスは変化しない。
3. サーバーコンソールで medstarve <患者ID> を実行する。ゲーム内では /medstarve <患者ID>。ゲーム内実行には command.medstarve の ACE が必要。例: add_ace group.admin command.medstarve allow
4. 対象の空腹が0になり即座にダウンする。別の医療職で診察し、カルテの傷一覧の「餓死」、点滴後の空腹値と蘇生時に満腹へ戻らないことを確認する。

## 診察時の患者写真

標準表示は7部位の人体図。写真と所見カードを使う場合は config.lua の Config.Examination.ChartPhoto を true にする。撮影を使うサーバーは Cfx.re の screenshot-basic を配置し、Medical より先に起動する。新規カルテの診察者側で一度だけ撮影し、写真はカルテと同じくリソースの稼働中だけサーバーのメモリに保持する。写真は勤務中の医療職が対象患者のカルテを開いた際にだけ転送する。撮影が使えない場合は「診察写真なし」と表示し、所見カードを一覧表示する。治療画面では既存の道具を対応する所見カードへドロップできる。

### カルテDB

起動時に oxmysql 経由で `mediora_medical_charts` を自動作成する。カルテはキャラクターIDと作成日時で保存し、診察・追記・治療・蘇生・請求時に更新する。再起動後の記録は閲覧専用。傷の現在状態と診察写真は従来どおりメモリで管理する。導入前に作成されたカルテは移行対象外。DB障害時はメモリ内で診療を継続し、保存に失敗した記録を稼働中に再試行する。

## 最新版との統合内容と注意点

- 従来のWasabi injurySyncのキャッシュと蘇生後の書き戻しは廃止し、この配布物のMedical受傷モデルへ移行した。
- タブレットの外観・起動スリープ演出・人型・ドラッグ中の追従カード・治療後の自動再表示・押印欄を維持。
- カルテは診察時の記録を保持。治療画面はサーバーが管理する現在症状と所持道具を使用する。
- 処置時の必要個数をサーバーで算出し、実際に消費した個数を処置対象のカルテへ記録する。
- 餓死・溺死は点滴を済ませてから蘇生する。外傷は蘇生前後に治療でき、蘇生時に残った外傷は引き継ぐ。処置済みの明細があれば、傷が残っている場合や蘇生前でも請求できる。成功時だけ請求済の印を付ける。
- 単価未指定の新道具は明細に「未設定」と表示し、請求送信を止める。単価はserver.luaのsupplyPricesへ追加する。
- 既存Toolsのpmediora_* IDを採用。冷却スプレー等の追加品はinstall/ox_inventory/items.luaを参照して定義する。
- Wasabiの変更とox_inventoryのアイテム登録は導入先へ手動適用する。点滴は pmediora_ivdrip を登録してから利用する。
- 受傷状態とカルテは再起動で消去される。切替前にあるWasabiの傷の移行は行わない。
- 検証はLua 85件とEdgeでの画面・ドラッグ・明細・請求ウィンドウ。FiveM実機のダメージ判定・道具消費・蘇生・請求は別途確認が必要。
