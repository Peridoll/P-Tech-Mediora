# Mediora Hospital

対象MLOは `D:\FiveM\dev\Novill Resource\hane_pillbox`。Hospitalは `hane_pillbox` を起動依存に指定している。マップ内には地下・ground・floor1〜4のデータがある。付属LuaはFXAP保護されており、作業地点の座標リストは確認できていない。初期の床清掃地点はMedicalの受付座標を使った仮配置で、hane_pillbox内の到達可能な床上にあるかゲーム内で確認する必要がある。

移行元は「☆ Hospital：病院：クラウド」。院内の登録スポットに業務が発生し、勤務中のEMSが現地の `ox_target` から対応する。完了するとCoreがMediora Pointsを記録し、作業は全員の対象から消える。作業中は他の隊員の開始を防ぎ、中断・離脱・切断時は引き継げる。

## ローカルで有効にする

1. 初期設定ではMedicalの患者VRと同じピルボックス受付座標で床清掃が発生する。現地のMLOに合わせて `config.lua` の `Hospital.hospitals` を調整する。各スポットに `coords` と `activity` を設定し、同じ作業地点を重複登録しない。病院ごとに同時発生上限と、必要なら `bucket` を指定する。
2. FiveMのresourcesに配置し、依存リソースの起動後に `ensure ptech_mediora_hospital` を追加する。Coreのポイント用DBも有効にする。
3. 勤務中のEMSで対象へ移動し、ターゲットから作業する。進行状況はCoreの共通プログレスバーに表示する。緊急出動時はXキーまたは `/hospitalcancel` で中断できる。ほかのクライアントリソースからは `exports.ptech_mediora_hospital:CancelWork()` で中断できる。

勤務終了・死亡・瀕死・作業地点からの離脱・車両への搭乗で作業を中断する。サーバー側でも勤務状態・行動不能・距離・経過時間を確認する。作業の開始ごとに受付番号を付け、過去の中断や完了の通信が次の作業に影響しないよう照合する。キャンセル後の反映は共有一覧の更新で最大約2秒、切断や離脱の解除は通常約1秒。通信が途切れた場合も作業時間に15秒を加えた期限で作業の占有を解除する。

## クラウド試案からの設定

- 業務別の変動クールタイムを経過した後、既定で5分ごとに抽選する。外れた場合は次回の抽選対象に残る。種類別と病院全体の上限を適用し、登録済みの空きスポットからランダムに選ぶ。
- クラウドの仮値は床清掃5〜15分・40%・4件、ゴミ回収10〜20分・35%・3件、ベッド清掃15〜30分・30%・3件、医療機器点検20〜40分・25%・2件、設備修理30〜60分・15%・2件。
- 清掃・設備整備・備品管理・事務の候補を業務定義に入れた。専用のモーション素材は未指定のため、作業に応じてGTA既存シナリオを使う。追加業務の抽選値、8秒の作業時間、1 MPはローカルの試作用設定。病院上限10件は設定例で、クラウドの「5〜10件」は以前の目安。抽選で発生するため最低件数は設けていない。将来の約30種類への拡張は業務定義とスポットの追加で行う。
- クールタイム開始時点はクラウドで未決定。ローカル既定の `spawn` は発生時から計測する。`complete` は完了時から計測するため、同一病院・業務につき完了まで次の発生を待つ。
- クラウド試案に座標指定はなく、受付以外の13業務は現地スポットを登録すると抽選対象になる。起動直後も初回クールタイムと抽選を待つ。業務とクールタイムは実行中のサーバーで共有され、リソース再起動でリセットされる。獲得済みポイントはCoreに保存される。

## ローカル検証

Pythonで `pip install -r tests/requirements.txt` の後、`python tests/test_activities.py` を実行する。FiveMのサービスを置き換え、共有作業の排他・引き継ぎ・古い通信の拒否・ポイント付与の失敗と再試行・Coreの進行表示と中断処理を検証する。MLO内の実際の位置とゲーム内表示は別途確認する。
