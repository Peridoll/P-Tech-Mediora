# Mediora seven-resource audit — 2026-10-14

Scope: develop tree, 7 resources, manifest and primary client/server implementations. No FiveM runtime access.

## Fixes in this branch
- Pharmacy: guard against malformed/nonnumeric Qbox job grade before comparing with minimum grade.
- Billing: handle missing ped values and database insertion exceptions without crashing the ox_lib callback.
- Settlement: handle database insertion exceptions without aborting the callback.
- Added offline Python unittest checks for manifest paths, independent module boundaries, and absence of active bank payout calls in draft-only modules.

## Critical integration blockers / confirmed observations
1. Procurement receipt metadata has only `amount`, `category`, `description`, while Settlement requires `orderId/id` and `issuedAt/date`. As implemented, procurement-issued receipts **cannot be submitted to Settlement**. Do not fake IDs; build an authoritative issuance ledger and a versioned signed/reference-only receipt contract.
2. Pharmacy recipes currently work on *player inventory*, not the Procurement hospital stash. The two are not an integrated supply chain.
3. Patients v0.1 test actors are client-local, so NPC tests do **not** prove network Escort, actual Wasabi injuries or Medical treatment.
4. Medical supports player observation and diagnosis reports; treatment and imaging are catalogue-only.
5. Billing and Settlement are *draft/review only*. No real billing, debit, reimbursement or payout should be inferred.
6. Procurement mutates stash, player cargo and receipt sequentially; rollback paths are not database-atomic. Simulate full inventory, simultaneous delivery and failed AddItem/RemoveItem before production.
7. Server/runtime start, NUI callbacks, item definitions, SQL tables, `ox_inventory` and Qbox compatibility, and Wasabi exports still require in-game verification.

## Test plan
- Run `python -m unittest discover -s tests -p 'test_*.py'` for source-level checks.
- Run Lua syntax checks (`luac -p`) on available Lua scripts where a parser is installed.
- Use sandboxed mock adapters for inventory/DB callback failures before enabling resource.
- Then use two actual players to verify permissions, distance, routing buckets, inventory and lifecycle.
- Never test real payout in production until server-issued ledger and exactly-once transfer are implemented.
